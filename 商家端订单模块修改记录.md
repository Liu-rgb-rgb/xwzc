## 一、前置操作：数据库加字段（必须先执行）

### 原因

`OrderMapper.xml` 里 `OrderDetailMap` 已经映射了 `merchant_remark` 列，但数据库 `orders` 表里没有这个字段。如果直接跑代码，MyBatis 查出来的 `merchant_remark` 是 null 不会报错，但 `updateMerchantRemark` 写入时会报列不存在。

### 执行的 SQL

```sql
ALTER TABLE `orders` 
ADD COLUMN `merchant_remark` VARCHAR(500) DEFAULT NULL 
COMMENT '商家备注' 
AFTER `remark`;
```

### 加完之后 orders 表的备注相关字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `remark` | VARCHAR(255) | 用户下单时填的备注 |
| `merchant_remark` | VARCHAR(500) | 商家后来补充的备注（本次新增） |

#### 方法 1：`pageAdminOrders` — 商家订单列表分页查询

```java
@Override
public IPage<OrderDetail> pageAdminOrders(long page, long pageSize, String status,
                                           String keyword, String startTime, String endTime) {
    List<OrderDetail> allRecords = baseMapper.selectAdminOrderList(status, keyword, startTime, endTime);

    // 手动分页（因为 LEFT JOIN + collection 的 XML 查询不能直接用 MyBatis-Plus 的 page 方法）
    int total = allRecords.size();
    int fromIndex = (int) ((page - 1) * pageSize);
    int toIndex = Math.min(fromIndex + (int) pageSize, total);

    List<OrderDetail> pageRecords;
    if (fromIndex >= total) {
        pageRecords = List.of();
    } else {
        pageRecords = allRecords.subList(fromIndex, toIndex);
    }

    pageRecords.forEach(this::enrichOrderDetail);

    Page<OrderDetail> result = new Page<>(page, pageSize, total);
    result.setRecords(pageRecords);
    return result;
}
```

**为什么不直接用 MyBatis-Plus 的分页插件：**
- XML 里用了 `LEFT JOIN order_item` + `<collection>` 来一对多映射订单项
- 这种写法如果套 MyBatis-Plus 的 `page()` 方法，分页会按行来算，一条订单有 3 个订单项就会被当成 3 条记录，分页数量不对
- 所以先查出全量结果，再在内存里截取当前页的数据

#### 方法 3：`updateOrderStatus` — 商家更新订单状态

```java
@Override
@Transactional(rollbackFor = Exception.class)
public Orders updateOrderStatus(Long orderId, String targetStatus) {
    Orders order = getById(orderId);
    if (order == null) {
        throw new BusinessException("订单不存在");
    }

    String currentStatus = order.getStatus();
    LocalDateTime now = LocalDateTime.now();

    switch (targetStatus) {
        case "PRODUCING":
            if (!"WAIT_CONFIRM".equals(currentStatus)) {
                throw new BusinessException("只有待接单状态的订单才能转为制作中");
            }
            order.setConfirmedAt(now);
            break;
        case "WAIT_DELIVERY":
            if (!"PRODUCING".equals(currentStatus)) {
                throw new BusinessException("只有制作中状态的订单才能转为待发货");
            }
            order.setProducedAt(now);
            break;
        case "DELIVERED":
            if (!"WAIT_DELIVERY".equals(currentStatus)) {
                throw new BusinessException("只有待发货状态的订单才能发货");
            }
            order.setShippedAt(now);
            break;
        default:
            throw new BusinessException("不支持的目标状态: " + targetStatus);
    }

    order.setStatus(targetStatus);
    updateById(order);
    return order;
}
```

**状态流转规则（写死了只能单向推进）：**

| 当前状态 | 可以转成 | 自动记录的时间戳字段 |
|---------|---------|-------------------|
| `WAIT_CONFIRM`（待接单） | `PRODUCING`（制作中） | `confirmedAt`（接单时间） |
| `PRODUCING`（制作中） | `WAIT_DELIVERY`（待发货） | `producedAt`（制作完成时间） |
| `WAIT_DELIVERY`（待发货） | `DELIVERED`（已发货） | `shippedAt`（发货时间） |
| 其他任何状态 | 传其他值 | 直接报错 |

**如果商家跳状态会怎样：** 比如订单还在 `WAIT_CONFIRM`，商家直接传 `DELIVERED`，会抛出 `"不支持的目标状态: DELIVERED"`。

**为什么要注入 `UserService`：**
- 订单表只存了 `user_id`，没存用户昵称
- 前端商家端列表要显示下单用户的昵称
- `xiuwen-order` 模块的 pom.xml 里没有依赖 `xiuwen-system` 模块，所以 Service 层不能直接用 UserService
- 把用户昵称的查询放在 Controller 层（`xiuwen-web` 模块同时依赖两个模块）

**`batchGetUserNicknames` 辅助方法的作用：**
- 列表接口可能返回 10 条订单，对应 10 个不同的 userId
- 如果每条订单都单独查一次 user 表，就是 10 次 SQL 查询（N+1 问题）
- 这个方法先收集所有不重复的 userId，一次性 `SELECT * FROM user WHERE id IN (...)` 查出来
- 返回 `Map<userId, nickname>`，然后遍历订单列表时直接从 Map 里取值

### 接口 2.3：修改订单状态

```
PUT /api/admin/orders/901/status
Content-Type: application/json
```

**请求 Body：**
```json
{
  "status": "PRODUCING"
}
```

**请求参数：**

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|--------|------|------|------|------|
| `orderId` | 路径 | Long | 是 | 订单 ID |
| `status` | Body | String | 是 | 目标状态，只能传 `PRODUCING`、`WAIT_DELIVERY`、`DELIVERED` |

**允许的状态流转：**

| 传的值 | 订单当前必须是什么状态 | 会自动更新的时间字段 |
|--------|---------------------|-------------------|
| `PRODUCING` | `WAIT_CONFIRM` | `confirmedAt` = 当前时间 |
| `WAIT_DELIVERY` | `PRODUCING` | `producedAt` = 当前时间 |
| `DELIVERED` | `WAIT_DELIVERY` | `shippedAt` = 当前时间 |

**如果传了不允许的状态，报错示例：**
```json
{
  "code": 400,
  "message": "只有待接单状态的订单才能转为制作中"
}
```

**成功响应示例：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 901,
    "orderId": 901,
    "orderNo": "XW202607140001",
    "status": "PRODUCING",
    "confirmedAt": "2026-07-28 10:30:00",
    "updatedAt": "2026-07-28 10:30:00"
  }
}
```
